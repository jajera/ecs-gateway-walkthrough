it to register as capacity on the cluster.

## Path variables

<div class="ecsx-cli">

```bash frame="terminal"
export PATH_NAME="${NAME}-ec2"
export CLUSTER="$PATH_NAME"
export GATEWAY="$PATH_NAME"
echo "path ready: CLUSTER=$CLUSTER GATEWAY=$GATEWAY"
```

```text
path ready: CLUSTER=ecs-gw-lab-ec2 GATEWAY=ecs-gw-lab-ec2
```

</div>

## Instance role

ECS container instances need an IAM role trusted by `ec2.amazonaws.com` with `AmazonEC2ContainerServiceforEC2Role`.

<div class="ecsx-cli">

```bash frame="terminal"
aws iam create-role \
  --role-name "${NAME}-ec2" \
  --assume-role-policy-document '{
    "Version": "2012-10-17",
    "Statement": [{
      "Effect": "Allow",
      "Principal": { "Service": "ec2.amazonaws.com" },
      "Action": "sts:AssumeRole"
    }]
  }' \
  --query 'Role.RoleName' --output text
```

```text
ecs-gw-lab-ec2
```

</div>

<div class="ecsx-cli">

```bash frame="terminal"
aws iam attach-role-policy \
  --role-name "${NAME}-ec2" \
  --policy-arn arn:aws:iam::aws:policy/service-role/AmazonEC2ContainerServiceforEC2Role
echo "instance role policy attached"
```

```text
instance role policy attached
```

</div>

## Instance profile

<div class="ecsx-cli">

```bash frame="terminal"
aws iam create-instance-profile --instance-profile-name "${NAME}-ec2" \
  --query 'InstanceProfile.InstanceProfileName' --output text
```

```text
ecs-gw-lab-ec2
```

</div>

<div class="ecsx-cli">

```bash frame="terminal"
aws iam add-role-to-instance-profile \
  --instance-profile-name "${NAME}-ec2" \
  --role-name "${NAME}-ec2"
echo "role added to instance profile"
```

```text
role added to instance profile
```

</div>


## Instance security group

Private-subnet instance; no inbound rules required for this lab (tasks use their own ENIs).

<div class="ecsx-cli">

```bash frame="terminal"
EC2_SG_ID=$(aws ec2 create-security-group \
  --group-name "${NAME}-ec2" \
  --description "ECS container instances for ${NAME}-ec2" \
  --vpc-id "$VPC_ID" \
  --query GroupId --output text)
export EC2_SG_ID
echo "EC2_SG_ID set (sg-<id>)"
```

```text
EC2_SG_ID set (sg-<id>)
```

</div>

## Create the cluster first

The ECS agent needs the cluster name at boot (`ECS_CLUSTER` in user data).

<div class="ecsx-cli">

```bash frame="terminal"
aws ecs create-cluster --cluster-name "$CLUSTER" \
  --query 'cluster.{name:clusterName,status:status}'
```

```text
{
    "name": "ecs-gw-lab-ec2",
    "status": "ACTIVE"
}
```

</div>

## Resolve ECS-optimized AMI

<div class="ecsx-cli">

```bash frame="terminal"
AMI_ID=$(aws ssm get-parameters \
  --names /aws/service/ecs/optimized-ami/amazon-linux-2023/recommended/image_id \
  --query 'Parameters[0].Value' --output text)
export AMI_ID
echo "AMI_ID set (ami-<id>)"
```

```text
AMI_ID set (ami-<id>)
```

</div>

## User data

Pins the agent to this path’s cluster:

<div class="ecsx-cli">

```bash frame="terminal"
cat > /tmp/${PATH_NAME}-userdata.sh <<EOF
#!/bin/bash
echo ECS_CLUSTER=${CLUSTER} >> /etc/ecs/ecs.config
EOF
wc -l /tmp/${PATH_NAME}-userdata.sh
```

```text
2 /tmp/ecs-gw-lab-ec2-userdata.sh
```

</div>

## Launch instance

Place the instance in a **private** subnet (no public IP). Outbound ECS agent and image traffic uses the NAT gateway. `t3.medium` leaves ENI headroom for `awsvpc` tasks.

<div class="ecsx-cli">

```bash frame="terminal"
INSTANCE_ID=$(aws ec2 run-instances \
  --image-id "$AMI_ID" \
  --instance-type t3.medium \
  --iam-instance-profile "Name=${NAME}-ec2" \
  --subnet-id "$PRIVATE_SUBNET_A" \
  --security-group-ids "$EC2_SG_ID" \
  --no-associate-public-ip-address \
  --user-data "file:///tmp/${PATH_NAME}-userdata.sh" \
  --tag-specifications "ResourceType=instance,Tags=[{Key=Name,Value=${PATH_NAME}}]" \
  --query 'Instances[0].InstanceId' --output text)
export INSTANCE_ID
echo "INSTANCE_ID set (i-<id>)"
```

```text
INSTANCE_ID set (i-<id>)
```

</div>

<div class="ecsx-cli">

```bash frame="terminal"
aws ec2 wait instance-running --instance-ids "$INSTANCE_ID"
aws ec2 describe-instances --instance-ids "$INSTANCE_ID" \
  --query 'Reservations[0].Instances[0].{state:State.Name,type:InstanceType,az:Placement.AvailabilityZone}'
```

```text
{
    "state": "running",
    "type": "t3.medium",
    "az": "ap-southeast-6a"
}
```

</div>

## Wait for registration

<div class="ecsx-cli">

```bash frame="terminal"
for i in $(seq 1 36); do
  COUNT=$(aws ecs list-container-instances --cluster "$CLUSTER" \
    --query 'length(containerInstanceArns)' --output text)
  echo "container instances: $COUNT"
  [ "$COUNT" != "0" ] && break
  sleep 10
done
```

```text
container instances: 0
container instances: 0
container instances: 1
```

</div>

Confirm without printing ARNs (they embed the account ID):

<div class="ecsx-cli">

```bash frame="terminal"
aws ecs list-container-instances --cluster "$CLUSTER" \
  --query 'length(containerInstanceArns)' --output text
```

```text
1
```

</div>

<Aside type="note">
  If the instance never registers, check the instance profile, user data (`ECS_CLUSTER`), that the NAT gateway is `available`, and that the private route table points `0.0.0.0/0` at the NAT.
</Aside>
