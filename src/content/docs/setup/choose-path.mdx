## Which should I pick?

For the **gateway** it makes no difference — same connector, same shared ALB, same managed
hostnames. The only question is who runs the host.

<div class="ecsx-pick not-content">
  <div class="ecsx-pick__col ecsx-pick__col--default">
    <div class="ecsx-pick__head">
      <img src={icon("icons/service/containers/Arch_AWS-Fargate_64.svg")} alt="" aria-hidden="true" width="30" height="30" loading="lazy" />
      <span>
        Fargate <span class="ecsx-pick__tag">default</span>
      </span>
    </div>
    <ul>
      <li>No servers to manage — AWS runs the host</li>
      <li>Bursty or variable load; scales to zero between tasks</li>
      <li>Least operational overhead</li>
      <li>Standard web services and APIs</li>
    </ul>
  </div>
  <div class="ecsx-pick__col ecsx-pick__col--ec2">
    <div class="ecsx-pick__head">
      <img src={icon("icons/service/compute/Arch_Amazon-EC2_64.svg")} alt="" aria-hidden="true" width="30" height="30" loading="lazy" />
      <span>Choose EC2 when</span>
    </div>
    <ul>
      <li>Steady, high utilization — often cheaper (Savings Plans, Spot, Graviton)</li>
      <li>You need GPUs or specific instance types Fargate doesn't offer</li>
      <li>Host-level control — privileged containers, kernel params, custom runtimes</li>
      <li>Bin-packing many small tasks onto fewer hosts, or an existing fleet</li>
    </ul>
  </div>
</div>

<Aside type="tip">Not sure? Pick **Fargate**. It is the lower-overhead default; move to EC2 only when you hit one of the reasons on the right.</Aside>

<Aside type="tip">In production, Fargate and EC2 services can share one cluster and one gateway. This lab keeps paths separate so you can run either alone.</Aside>

## Shared teardown reminder

After you finish a path's own teardown page, delete the shared VPC and IAM roles only when you are
done with **both** paths (see the teardown page you used — it ends with shared cleanup).
