## Path variables

<div class="ecsx-cli">

```bash frame="terminal"
export PATH_NAME="${NAME}-fargate"
export CLUSTER="$PATH_NAME"
export GATEWAY="$PATH_NAME"
echo "path ready: CLUSTER=$CLUSTER GATEWAY=$GATEWAY"
```

```text
path ready: CLUSTER=ecs-gw-lab-fargate GATEWAY=ecs-gw-lab-fargate
```

</div>

## Cluster

This cluster is independent of any EC2-path cluster.

<div class="ecsx-cli">

```bash frame="terminal"
aws ecs create-cluster --cluster-name "$CLUSTER" \
  --query 'cluster.{name:clusterName,status:status}'
```

```text
{
    "name": "ecs-gw-lab-fargate",
    "status": "ACTIVE"
}
```

</div>

<div class="ecsx-cli">

```bash frame="terminal"
aws ecs describe-clusters --clusters "$CLUSTER" \
  --query 'clusters[0].{name:clusterName,status:status}'
```

```text
{
    "name": "ecs-gw-lab-fargate",
    "status": "ACTIVE"
}
```

</div>

## Gateway

Creates an account-level gateway with a **host-shared ALB** configuration. Subnets must be the **public** pair (internet-facing scheme). No ALB exists yet — ECS creates it when the first compatible service connects.

Raw `create-gateway` / `associate` responses include ARNs (account ID). Redirect them and confirm with a trimmed query.

<div class="ecsx-cli">

```bash frame="terminal"
aws ecs create-gateway \
  --name "$GATEWAY" \
  --infrastructure-role-arn "$GATEWAY_INFRA_ROLE_ARN" \
  --configuration "{
    \"hostSharedAlb\": {
      \"scheme\": \"internet-facing\",
      \"networkConfiguration\": {
        \"subnets\": [\"${PUBLIC_SUBNET_A}\", \"${PUBLIC_SUBNET_B}\"],
        \"ipAddressType\": \"ipv4\"
      }
    }
  }" >/dev/null
```

```text
(no stdout — success is silent)
```

</div>

<div class="ecsx-cli">

```bash frame="terminal"
aws ecs describe-gateway --gateway "$GATEWAY" \
  --query 'gateway.{name:name,status:status,accessType:accessType}'
```

```text
{
    "name": "ecs-gw-lab-fargate",
    "status": "ACTIVE",
    "accessType": "PUBLIC"
}
```

</div>

Status should be `ACTIVE`. This gateway is independent of any EC2-path gateway.

<Aside type="caution">
  Name, scheme, subnets, and IP address type are immutable after create. Deletion protection defaults **on**; [teardown](/fargate/teardown/) turns it off before `delete-gateway`.
</Aside>

<Aside type="note">If create fails with an assume-role / `PassRole` error, wait about a minute for IAM and retry (see [Infra roles](/setup/infra-roles/)).</Aside>

## Associate

A service can use a gateway only after the gateway is associated with that service’s cluster.

<div class="ecsx-cli">

```bash frame="terminal"
aws ecs associate-gateway-with-cluster \
  --gateway "$GATEWAY" \
  --cluster "$CLUSTER" >/dev/null
```

```text
(no stdout — success is silent)
```

</div>

<div class="ecsx-cli">

```bash frame="terminal"
aws ecs list-gateway-cluster-associations --gateway "$GATEWAY" \
  --query 'gatewayClusterAssociations[].status'
```

```text
[
    "ACTIVE"
]
```

</div>

Expect `[ "ACTIVE" ]`. Full association payloads include ARNs — do not paste them into tickets.

The cluster and gateway are ready, but **no ALB exists yet** — it is provisioned when the first service connects. Next you deploy the two demo services, **Orders** (`-a`) and **Catalog** (`-b`), each with a gateway connector.
