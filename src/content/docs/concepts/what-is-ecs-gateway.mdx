Amazon ECS Gateway is an **account-level** resource that holds ingress configuration and
security standards. You associate it with clusters; services opt in with a

<Tooltip term="gateway-connector" label="gateway connector" />. ECS then provisions and manages the load balancer path in your account.

<Aside type="note">Creating a gateway provisions **nothing**. The first Application Load Balancer appears when the first compatible service connects.</Aside>

## How we got here

ECS Gateway doesn't replace anything — it's a shortcut for ingress plumbing teams already set up by
hand. Here's what changes.

### Is it the right fit?

<div class="ecsx-gate not-content">
  <span class="ecsx-gate__q">Does the service serve inbound HTTP(S)?</span>
  <div class="ecsx-gate__paths">
    <div class="ecsx-gate__branch ecsx-gate__branch--no">
      <span class="ecsx-gate__verdict">No → skip the gateway</span>
      <span class="ecsx-gate__ex">Batch, ETL, queue / stream consumers. Nothing to route — give them outbound access via NAT instead.</span>
    </div>
    <div class="ecsx-gate__branch ecsx-gate__branch--yes">
      <span class="ecsx-gate__verdict">Yes → read on</span>
      <span class="ecsx-gate__ex">Web apps and APIs that answer requests on a listening container port.</span>
    </div>
  </div>
</div>

<div class="ecsx-fit not-content">
  <div class="ecsx-fit__col ecsx-fit__col--use">
    <h4>Use a gateway</h4>
    <ul>
      <li>A fleet of services needing public HTTPS</li>
      <li>Platform should own LB, certs, and routing</li>
      <li>Happy with host-based routing on HTTPS 443</li>
      <li>
        Managed <code>*.ecs.&lt;region&gt;.on.aws</code> hostname is fine
      </li>
      <li>
        Tasks use <Tooltip term="awsvpc" label="awsvpc" /> networking
      </li>
    </ul>
  </div>
  <div class="ecsx-fit__col ecsx-fit__col--diy">
    <h4>Wire an ALB yourself</h4>
    <ul>
      <li>Need path-based routing or non-443 ports</li>
      <li>Need a custom domain on the load balancer</li>
      <li>Want hands-on control of ALB, WAF, listeners</li>
      <li>Just one service — manual is faster</li>
    </ul>
  </div>
</div>

## What a connected service creates

Each <Tooltip term="gateway-route" label="gateway route" /> is one service connected to one
gateway. Shared resources are reused across services on the same gateway; per-route resources are
created once per service.
